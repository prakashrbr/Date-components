2. Date Range Picker

A date input that allows users to select a start date and end date as a continuous period.

Goal: make it quick and clear to select a date range while helping users understand the duration and avoid invalid ranges.

Examples

  • Treatment period
  • Medication period
  • Procedure → follow-up
  • Lab monitoring period
  • Clinical history
  • Reporting period
  • Appointment availability

When To Use

  • Both a start and end date are required.
  • The dates represent one continuous period.
  • Seeing the dates together provides useful context.
  • The user may benefit from calendar-based range selection.
  • Common date ranges can be provided as quick actions.

When Not To Use

  • Only one date is required → Known Date / Calendar Date Picker
  • The dates represent two unrelated events.
  • Time is also required → Date + Time Picker
  • The date is approximate or partially known → Clinical Date
  • Multiple separate dates need to be selected.

Input Rules

  • Provide clearly labelled Start date and End date.
  • Allow direct typing as well as calendar selection.
  • Support keyboard input.
  • Allow the same date for start and end when a single-day range is valid.
  • Use 4-digit years where appropriate.
  • Keep the selected range synchronized between the input and calendar.

Behavior

  • User selects the start date.
  • User selects the end date.
  • The dates between them are highlighted as the selected range.
  • Preview the potential range when hovering or focusing on an end date.
  • Allow either date to be edited independently.
  • Provide Cancel and Done when the selection should not be committed immediately.
  • Start and end dates use a strong selected state.
  • Dates between them use a lighter range state.
  • The range should appear visually continuous.
  • Do not require the start date to appear in the left calendar and the end date in the right calendar.

Smart Behavior

The component can provide contextual assistance:

  • Recommended date ranges
  • Common clinical periods
  • Relevant events
  • Minimum/maximum dates
  • Dependent date constraints
  • Ongoing periods
  • Duration of the selected range
Recommendations should guide, not force the user.

Validation & Constraints

  • Missing start date
  • Missing end date
  • Invalid date
  • End date before start date
  • Date outside allowed range
  • Unavailable dates
  • Conflicting clinical dates
  • Invalid clinical sequence
  • If the user picks an end date that is before the start date, that date becomes the new start date.

Accessibility

  • Clearly label Start and End dates.
  • Support complete keyboard interaction.
  • Provide visible focus states.
  • Don't rely on color alone to communicate the range.
  • Clearly announce start, end, and in-range dates to screen readers.
  • Ensure disabled dates are understandable.
  • Maintain predictable focus when moving between dates.
  • Provide accessible error messages.
  • Ensure adequate touch targets.

Anatomy

The callouts are measured from the rendered component, so they follow each design system's layout.

  1. Input field – Start and end dates, each typed or picked, separated by an arrow.
  2. Quick ranges – Custom, Recommended, and common periods like This week.
  3. Month / year navigation – Moves each month; the title opens the year list.
  4. Weekday header – Days of the week, starting on Monday.
  5. Range calendar – Two months; start and end are strong, days between use a lighter band.
  6. Keyboard navigation guide – How to move and select with the keyboard.
  7. Duration and actions – Length of the range, plus Cancel and Done to confirm it.

Range Selection

How a range is built inside the calendar. Both demos are interactive.

  • Hovering or focusing a date previews the range before it's chosen.
  • Picking a date before the start makes it the new start.

1. Recommended Dates

Where To Use
  • A specific date range is preferred based on clinical or workflow rules.
  • The system has enough context to identify a suitable range.
  • Timing of a follow-up, review, procedure, or monitoring period matters.
  • Multiple valid ranges are available, but one better matches the workflow.
When To Use
  • A meaningful recommendation can be calculated.
  • The recommendation has a clear reason.
  • The user benefits from seeing the preferred range before making a selection.
  • The recommendation can change based on patient, workflow, availability, or clinical context.
How To Use
  • Identify a valid date range based on the current context.
  • Highlight the recommended range in the calendar.
  • Show why the range is recommended.
  • Keep other valid dates selectable.
  • Allow the user to modify or select a different range.

2. Contextual Quick Actions

Where To Use
  • When the system has enough clinical or workflow context to recommend a range.
  • When there are multiple valid ranges but some are more appropriate for the current context.
  • For treatment periods, monitoring windows, review periods, and other continuous date ranges.
  • When the reason behind the recommendation can be clearly explained.
When To Use
  • When a recommendation is based on a defined rule, clinical guideline, or workflow condition.
  • When the recommended range can be calculated from relevant dates or context.
  • When showing the reason helps the user make an informed selection.
  • When more than one valid recommendation may exist.
How To Use
  • Show recommended ranges as selectable options.
  • Display the date range prominently.
  • Provide a short explanation for why the range is recommended.
  • Include relevant supporting information when available.
  • Keep the recommendation optional; users can still select a custom range.
  • Update recommendations when the underlying context changes.
  • Avoid showing recommendations when there is insufficient context.

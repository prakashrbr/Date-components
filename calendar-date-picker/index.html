A Calendar Date Picker allows users to select a date from a visual calendar.

Goal: make date discovery quick and provide useful calendar context.

Examples: appointment date, procedure date, follow-up date, scheduled admission.

When To Use

  • When the user needs to find and select a date.
  • When calendar context helps the user make a decision.
  • When availability, events, or clinical rules affect date selection.
  • When the date is relatively close to the current date.

When Not To Use

  • Known Date → when the date is already known and can be entered directly.
  • Date Range → when selecting a start and end date.
  • Date-Time → when both date and time are required.
  • Clinical Date → when the date is approximate, partial, or unknown.

Use a calendar when seeing the dates helps the user decide.

Input Rules

  • Allow direct date entry alongside calendar selection.
  • Use clear date formatting and locale-appropriate ordering.
  • Support keyboard navigation and selection.
  • Prefer four-digit years.
  • Avoid requiring unnecessary leading zeros.

Behavior

  • Users should be able to:
    1. Type a date directly.
    2. Open the calendar.
    3. Navigate between months and years.
    4. Select a date.
    5. Navigate and select using the keyboard.
    6. Return to today when useful.
  • Avoid:
    1. Automatically changing the selected date.
    2. Automatically moving focus between fields.
    3. Hiding the current selection.
    4. Requiring calendar navigation when direct entry is faster.

Smart Behavior

The calendar can adapt to the clinical context by showing:

  • Today
  • Recommended dates
  • Dates with events
  • Unavailable dates
  • Clinical date ranges
  • Relevant scheduling information
Smart behavior should reduce effort while keeping the clinician in control.

Recommendation Rules

Since your component has Recommended Dates, establish the principle here.

  • Recommendations must be based on clear clinical or workflow rules.
  • Always provide a reason for a recommendation.
  • Recommendations should guide, not force, the user's choice.

This prevents the smart functionality from becoming arbitrary.

Validation & Constraints

  • Prevent invalid or clinically restricted dates.
  • Support minimum, maximum, and dependent dates.
  • Explain relevant restrictions when a date is unavailable.

Anatomy

The callouts are measured from the rendered component, so they track each design system's layout.

  1. Input field – Displays the selected date. Allows manual input in mm/dd/yyyy format.
  2. Quick actions – Provides shortcuts for common date selections and recommendations.
  3. Month / year navigation – Navigates between months and years.
  4. Weekday header – Displays days of the week to provide context.
  5. Calendar grid – Days of the month, clickable for selection.
  6. Keyboard navigation guide – A guide to using the keyboard for navigating and selecting dates.

Functionalities

Each demo is interactive. Tooltips are pinned open to match the spec, and hovering other dates moves them. Picking a date closes the calendar; click the field to open it again.

1. Recommended Dates

Where To Use
  • When a date is clinically or operationally preferred.
  • When the system has enough context to identify a better date.
  • Useful for follow-ups, reviews, procedures, and appointments.
When To Use
  • When there is a recommended time window.
  • When availability or clinical rules influence the choice.
  • When choosing one date from multiple valid options.
How To Use
  • Mark the date clearly as Recommended.
  • Provide a short reason on hover/focus.
  • Keep other valid dates selectable.
  • Don't recommend a date without a clear reason.

2. Dates With Events

Where To Use
  • When a date has one or more relevant events.
  • Useful for appointments, procedures, follow-ups, and clinical activities.
When To Use
  • When existing events may influence the user's date selection.
  • When the user needs quick visibility into scheduled activities.
How To Use
  • Mark the date with a subtle event indicator.
  • Show event details on hover or focus.
  • Display only relevant event information.
  • Keep the date selectable unless the event makes it unavailable.

3. Contextual Quick Actions

Where To Use
  • When common date choices are predictable for the workflow.
  • Useful for appointments, follow-ups, procedures, and clinical documentation.
  • When shortcuts can reduce unnecessary calendar navigation.
When To Use
  • When users frequently select relative or clinically relevant dates.
  • When the current context provides meaningful actions such as Today, Recommended, Tomorrow, or Yesterday.
  • When a quick action can save repeated date selection.
How To Use
  • Show only actions relevant to the current context.
  • Keep actions short and easy to scan.
  • Place them above the calendar for quick access.
  • Limit the number of actions to avoid clutter.
  • Make the result of each action clear before selection.
Few Examples
  • Follow-up: Recommended · +7 days · +14 days
  • Appointment: Today · Tomorrow · This week
  • Procedure: Recommended · Today · Tomorrow
  • Medication review: +14 days · +30 days · Recommended
  • Discharge: Today · Tomorrow
  • Clinical documentation: Today · Yesterday · 7 days ago
  • Lab monitoring: Recommended · +7 days · +30 days

Year Change

Select the month title to change the year. The spec opens a floating year picker that scrolls, centered on the current year. Ant Design shows a decade panel, and MUI shows a scrolling year list.

5. Time Picker With Presets

A time input that allows users to enter an exact time or quickly select from commonly used preset times.

Goal: Help users enter time faster while reducing manual entry and time-format errors.

Examples

  • Appointment time
  • Procedure time
  • Medication schedule
  • Patient arrival time
  • Follow-up time
  • Clinical reminders
  • Observation/check time

When To Use

  • A small set of times is frequently used.
  • Users often select predictable times.
  • Quick selection can reduce repetitive typing.
  • The exact time may still need to be entered manually.
  • Presets can be determined by the current workflow or context.

When Not To Use

  • Every time is equally likely.
  • The user usually knows an exact historical time.
  • Presets would add more choices than they remove.
  • The time cannot be meaningfully predicted from the workflow.

Input Rules

  • Allow direct time entry.
  • Support 12-hour or 24-hour format based on locale/system configuration.
  • Validate hours and minutes independently.
  • Minutes should support 00–59.
  • Allow configurable time intervals such as 5, 10, 15, 30, or 60 minutes.
  • Preserve exact entered times; don't automatically round them.

Presets

Presets can be different types depending on context:

  • Fixed – Specific commonly used times, e.g. 8:00 AM · 8:30 AM · 9:00 AM
  • Relative – Time calculated from the current time, e.g. Now · +15 min · +30 min · +1 hr

Behavior

  • Selecting a preset immediately populates the input.
  • The selected time remains editable.
  • Presets should update based on context when applicable.
  • Don't silently change a user's selected time.
  • If a preset becomes unavailable, explain why.
  • Keep the exact-time input available at all times.
  • Avoid presenting a large list of preset times.

Smart Behavior

The component can intelligently provide:

  • Now when the current time is relevant.
  • Recommended times based on workflow rules.
  • Available times when scheduling.
  • Relative times for reminders or follow-ups.
  • Context-specific common times.
  • Conflict or availability information.
Recommendations should always be understandable and guide rather than force the user.

Validation & Constraints

  • Invalid hour
  • Invalid minute
  • Missing time
  • Unavailable time
  • Time outside allowed range
  • Conflicting time
  • Clinical/workflow restrictions

For actual clinical events, avoid rounding the entered time.

Accessibility

  • Presets must be keyboard accessible.
  • Use clear labels for each preset.
  • Provide visible selected/focus states.
  • Don't rely on color alone.
  • Maintain logical keyboard order.
  • Ensure preset buttons have adequate touch targets.
  • Screen readers should clearly communicate the preset's resulting time.

Anatomy

Callouts are measured from the rendered component, so they follow each design system's layout.

  1. Label – Names the time being recorded.
  2. Time input – Type an exact time; it's kept as entered.
  3. Format switch – 12-hour or 24-hour display; the time itself doesn't change.
  4. Relative preset – Now, +15 min, +1 hr: calculated from the current time.
  5. Fixed presets – Commonly used times for this workflow.

States

Field and preset states.

Presets

  • Selecting a preset immediately fills the input, and the time stays editable.
  • The preset that set the time stays highlighted until the time is changed.
  • Relative presets are calculated when used; hover or focus one to see the time it sets.
  • Unavailable presets are struck out and explain why; recommended ones say why they're suggested.

Validation

Hours and minutes are checked separately, and the time is checked against the allowed range, blocked times and conflicts.
